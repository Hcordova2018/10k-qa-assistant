# 10-K Q&A Assistant

A small local tool for asking natural-language questions across a handful of
companies' SEC 10-K filings, and getting answers that cite exactly which
company and section (Risk Factors, MD&A, Financial Statements, etc.) the
information came from.

Everything runs locally: filings live in a folder on your machine, and the
vector database is a local [Chroma](https://www.trychroma.com/) instance —
no cloud database, no accounts.

## How it works (the plan)

There are four stages. We're building them in order:

1. **Load** — read raw 10-K filings from `data/` and split each one into its
   standard sections (Business, Risk Factors, MD&A, Financial Statements)
   instead of chopping text into arbitrary fixed-length blocks. Splitting by
   section means each stored chunk already has meaning — "this came from
   Apple's Risk Factors" is a far more useful citation than "this came from
   character 14,502."
2. **Chunk** — within a section, split further only if needed (some sections,
   like Risk Factors, are long), while keeping the section/company/date tags
   attached to every piece.
3. **Store** — embed each chunk and store it in a local Chroma collection,
   along with its metadata (company, filing date, section).
4. **Query** — take a question, find the most relevant chunks, and return an
   answer with citations back to (company, section, filing date).

Steps 1-3 (load, chunk, store) are done. `app/loader.py` parses a filing's
HTML and splits it into the four sections above; `app/chunker.py` breaks each
section into ~1500-character chunks (with a little overlap between them) sized
for embedding, while every chunk keeps its company/ticker/fiscal year/section
tags for citations. `app/vectorstore.py` embeds each chunk with a small local
model (all-MiniLM-L6-v2, no API key needed) and stores it in Chroma, and can
search the stored chunks by meaning. Step 4 (`app/query.py`) is next.

## Project structure

```
10k-qa-assistant/
├── data/                 # Your downloaded 10-K filings go here (see below)
├── app/                  # The actual library code
│   ├── config.py         # Paths and constants shared by everything else
│   ├── loader.py         # Reads filings, splits into sections
│   ├── chunker.py        # Splits long sections into embeddable chunks
│   ├── vectorstore.py    # Wraps chromadb: add chunks, search chunks
│   └── query.py          # ask(question) -> answer + citations   [NEXT]
├── scripts/
│   ├── ingest.py         # CLI: build the vector database from data/
│   └── ask.py            # CLI: ask a question from the command line
├── chroma_db/            # Generated by ingest.py — the local vector DB
│                         # (not checked into git; rebuild anytime)
└── requirements.txt
```

`loader.py`, `chunker.py` and `vectorstore.py` are implemented; `query.py`
and the scripts are still stubs with docstrings describing what they'll do —
this keeps the shape of the project visible from day one, even before the
logic exists.

## Setting up the `data/` folder

You'll download filings yourself from
[SEC EDGAR](https://www.sec.gov/edgar/search/). To keep the loader simple,
organize them like this — one subfolder per company, one file per filing:

```
data/
├── AAPL/
│   └── AAPL_2023_10K.htm
├── MSFT/
│   └── MSFT_2023_10K.htm
└── TSLA/
    └── TSLA_2023_10K.htm
```

Using the folder name as the ticker and the filename to encode the year
means the loader can figure out "which company, which filing" from the file
path, without having to guess it from the document text. We'll finalize the
exact filename pattern when we write `loader.py`, but starting your
downloads with this layout will keep things simple.

10-K filings from EDGAR are usually plain HTML — that's what `loader.py`
will expect to parse first.

## Setup

You'll need Python and a virtual environment.

> **Windows note:** Chroma's embedding model runs on `onnxruntime`, which
> needs a recent Microsoft Visual C++ runtime. If Python exits silently (or
> with "access violation") as soon as anything is embedded, install the
> latest
> [Visual C++ Redistributable (x64)](https://aka.ms/vs/17/release/vc_redist.x64.exe)
> and try again. You can check with
> `.venv\Scripts\python -c "import onnxruntime"` — it should print nothing
> and not crash.

```powershell
# From the project folder:
python -m venv .venv
.venv\Scripts\activate

pip install -r requirements.txt
```

## Running it (once built)

```powershell
# 1. Put your downloaded 10-K filings in data/ (see layout above)

# 2. Build the vector database
python scripts/ingest.py

# 3. Ask a question
python scripts/ask.py "What supply chain risks did Apple report in 2023?"
```

A simple command-line function is the first target — no UI yet. Once that
works reliably, a UI can be layered on top without changing anything
underneath.

**Sanity-checking the pieces built so far:** since `ingest.py` isn't built
yet, you can run each module directly:

```powershell
.venv\Scripts\python -m app.loader       # one line per section found
.venv\Scripts\python -m app.chunker      # chunk counts/sizes per section
.venv\Scripts\python -m app.vectorstore  # rebuild chroma_db/, run test searches
```

The first `app.vectorstore` run downloads the ~80 MB embedding model to
`~/.cache/chroma`; after that it runs offline.
